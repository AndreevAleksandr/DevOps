### Задача 1

**Условия**
1. Создать нового пользователя с правами админа
2. Настроить SSH-Доступ по ключам
3. Запретить вход по паролю и root-логин
4. Настроить базовый firewall

>Использую OS Ubuntu 24.04
---
**Практика**

- Создаем пользователя: ` sudo useradd -m -s /bin/bash mitest `
- Задаем пароль (временно): ` sudo passwd mitest `
- Выдаем права админа: ` sudo usermod -aG sudo mitest `
- Проверяем что пользователь создан: ` id mitest `
- Переходим в пользователя чтобы проверить что права админа выданы: ` su - mitest ` / ` sudo whoami `

- Сгенерировал SSH ключ через Powershell (windows): ` ssh-keygen `
- Перекинул ключи на VM: ` ssh-copy-id -i C:/Users/User/.ssh/id_ed25519.pub mitest@192.168.0.38 `
> Столкнулся с проблемой что ` ssh-copy-id ` не работает через Powershell, перекинул ключ через GitBash
- Изменил sshd_config файл:
	- Запретил вход для root: ` PermitRootLogin no `
	- Разрешил вход по ключу: ` PubkeyAuthentication yes `
	- Запретил вход по паролю для всех: ` PasswordAuthentication no `
	- Запретил пустые пароли: ` PermitEmptyPasswords no `
- Перезапустил ssh сервис и проверил статус: ` sudo systemctl restart ssh ` / ` sudo systemctl status ssh `
> При проверки на вход без пароля, столкнулся с проблемой что я все еще мог заходить по паролю
> Оказалось что в файле /etc/ssh/sshd_config.d/50-cloud-init.conf было установлено значение ` PasswordAuthentication yes `, при его изменении доступ по паролю закрылся
> Дальше оказалось что если публичный ключ от ssh лежит в папке (.ssh) пользователя, то только под этим пользователем возможен вход по ключу

- Установил ufw: ` apt install ufw `
- Добавил правило для разрешения трафика по 22ому порту: ` ufw allow ssh `
- Добавил доп. порты на будущее: ` ufw allow 8081/tcp ` / ` ufw allow 8443/tcp `
- Включил фаервол: ` ufw enable `
- Проверил статус: ` ufw status verbose `
- Выключил ufw: ` ufw disable `

- Установил iptables: ` apt install iptables `
- Сбросил все правила: ` iptables -F `
- Разрешил loopback трафик: ` iptables -A INPUT -i lo -j ACCEPT `
- Разрешил установленные соединения: ` iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT `
- Добавил несколько портов в разрешенные: ` iptables -A INPUT -p tcp --dport 22,8081,8443 -j ACCEPT `
- Запретил весь остальной трафик: ` iptables -A INPUT -j DROP `
- Установил пакет для сохранения настроек: ` apt install iptables-persistent -y `
- Проверил статус: ` iptables -L -n -v `

### Разбор команд

- Выполнение команд с правами root: ` sudo `
- Утилита для создания нового пользователя: ` useradd `
- Флаг для создания домашней директории /home/mitest: ` -m `
- Установка оболочки bash по умолчанию: ` -s /bin/bash `

- Утилита для изменения пароля: ` passwd `
- Пароль хэшируется алгоритмом SHA-512 и сохраняется в /etc/shadow

- Утилита для модификации пользователя: ` usermod `
- Флаг, чтобы пользователь небыл удален из всех групп: ` -a `
- Указываем список дополнительных групп: ` -G `
- Группа администраторов: ` sudo `

- Переключение на другого пользователя с загрузкой его окружения: ` su - `
	- Без ` - ` сохранится окружение текущего пользователя

- Утилита для генирации пары ключей (приватный и публичный): ` ssh-keygen `
- Утилита для автоматического копирования публичного ключа на сервер: ` ssh-copy-id `
- Флаг, указывает путь к публичному ключу: ` -i `

- Пакетный менеджер debian/Ubuntu: ` apt `
- Команда установки: ` install `
- Простой интерфейс для iptables: ` ufw `

- Разрешить трафик: ` ufw allow `
- Именованное правило (порт 22/tcp): ` ssh `
- Разрешить TCP трафик: ` 8081/tcp ` / ` 8443/tcp `
- Запретить трафик: ` ufw deny `
- Запретить или отправить ответ: ` ufw reject `
- Активируем firewall: ` ufw enable `
- Отключаем firewall: ` ufw disable `

- Мощный и гибкий firewall, но сложный в настройке: ` iptables `
- Флаг очистит все правила во всех цепочках: ` -F `
- Добавляем правило в цепочку INPUT (Входящий трафик): ` -A INPUT `
- Интерфейс loopback (localhost): ` -i lo `
>Loopback нужен для внутренней коммуникации процессов
- Принимаем: ` -j ACCEPT `
- Используем модуль state (Отслеживание состояния соединений): ` -m state `
- Состояния: ` --state ESTABLISHED, RELATED `
	- Уже установленный соединения: ` ESTABLISHED `
	- Связанные соединения: ` RELATED `
- Протокол TCP: ` -p TCP `
- Порты назначения: ` --dport 22,8081,8443 `
- Отбрасываем пакет: ` -j DROP `

- Пакет для автоматического сохранения / загрузки правил: ` iptables-persistent `
- Правила сохраняются в /etc/iptables/rules.v4 (IPv4) или v6 (IPv6)

- Флаг показывает список правил: ` -L `
- Флаг показывает IP и порты без имен: ` -n `
- Флаг подробного вывода: ` -v `
